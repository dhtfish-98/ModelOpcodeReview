# Bounded defensive contract

Input is one caller-selected local immutable byte sequence or regular file. It is reviewed as pickle, ZIP32 or NPY. Auto mode uses content magic; inside ZIP, `.pkl`/`.pickle`, protocol-prefix content, NPY magic and `.npy` entries are selected. A `.npy` name must contain NPY structure. Other entries stay OPEN. Unknown root bytes are attempted as pickle and become OPEN on a decoding/stack error. Input bytes/hash remain unchanged; no target code or model framework is invoked.

The trusted Python standard library decodes opcodes through `pickletools.genops`. New code implements semantic state independently: identities for primitive strings/bytes/scalars, containers, globals and unknown constructed values; a genuine stack and mark index stack; memo stores the actual top value and GET returns that same identity. MEMOIZE uses the memo's current length, including sparse/overwritten keys. POP/DUP/POP_MARK and list/tuple/dict/set updates preserve symbolic identities and graph edges. Keys are checked for definitely unhashable containers and unresolved hash behavior. Graph traversal has its own work budget and cycles are handled without recursion.

Protocols 0/1 may be implicit; explicit PROTO must start a stream and be 2..5. Declared lower protocol than an opcode, missing required protocol header, unknown bytes or invalid stack are OPEN. Legacy GLOBAL under protocol 4/5 is explicitly noncanonical OPEN while its reference is retained. ASCII legacy strings use the normal Python-3 default string interpretation; non-ASCII legacy strings are OPEN because caller decoding options differ. Names with control/NUL, unresolved STACK_GLOBAL operands, undefined memo references and unknown extension/persistent/buffer values remain OPEN. The global SHA identifier frames an eight-byte big-endian module-byte length, UTF-8/surrogatepass module bytes, then name bytes; no raw name is emitted.

FRAME sizes are checked against remaining bytes, nested/overlapping frames are refused, no opcode may cross a boundary, and STOP must consume the frame completely if it is inside one. Adjacent frames and unframed chunks are supported; zero-length frames are outside this strict profile. STOP requires exactly one symbolic root and no remaining mark. This stricter structural profile need not accept everything any Unpickler implementation happens to tolerate. Streams use separate memo stores. Multiple streams are explicitly OPEN because the actual consumer might preserve its memo across loads. Analysis stops at invalid semantics, retaining all previously observed findings; bytes after that failure have not been proved covered.

Every imported reference remains OPEN. The independent fixed FAIL rule covers modules rooted at os/posix/nt/subprocess/socket/ctypes/pickle/_pickle/runpy/urllib/requests and selected exact builtins/__builtin__ names eval/exec/compile/open/__import__/getattr. This policy may flag legitimate references and does not represent a complete risk taxonomy. All other references, including upstream benign-model allowlisted constructors, remain OPEN. Object construction and mutation hooks record target identity/reference digest and edges, but their return values, true class identity, nested byte payload behavior and actual runtime bindings remain unknown. No general data-flow or full malware proof is claimed.

ZIP is a single-disk ZIP32 profile with producer IDs DOS/Unix/macOS, required version 10 or 20 (deflate/descriptors require 20), methods stored/deflate and flags UTF-8/descriptor only. It validates one final EOCD, exact central span, sequential matching local records, identical names/flags/method/time/CRC/lengths, all-zero or exact local descriptor tuples, signed/unsigned exact descriptors, no physical gaps/preamble/trailing bytes, deflate exact EOF/size and payload CRC. CRC mismatch is OPEN and selected payload references still survive. PyTorch's legacy behavior of ignoring CRC is deliberately not reproduced. ZIP64, multipart, encryption, unknown flags/methods/platforms and unknown extras are OPEN. Only structurally bounded timestamp fields and PyTorch 0xFB Z-filled alignment extras are accepted; none control sizes/offsets. Comments are ignored as content and never echoed. No member is extracted.

Every ZIP entry contributes to size/member budgets. Duplicate raw/case/NFKC aliases and file/directory prefix conflicts are FAIL. Names reject absolute paths, raw parent/dot/empty components, backslashes, colon, controls/NUL, non-NFC names, normalization-created separators, reserved Windows basenames and trailing normalized dot/space. Only regular files and empty directories fit the selected type profile; links/special or contradictory types are FAIL even when the producer is DOS. ZIP format has no general hardlink semantics; unknown extension semantics are OPEN. An opaque storage or metadata entry has no model semantic validation and causes OPEN even if recognized by a framework filename.

NPY magic, versions 1/2/3, little-endian header size, bounded header extent, newline and 16-byte alignment are checked (accepting older and current 64-byte writers). Headers use bounded AST parsing and `ast.literal_eval`; only exactly descr/fortran_order/shape keys with no duplicates are accepted. Dimensions are an integer tuple, excluding bool, with a bounded product. Supported dtype grammar: optional endian marker, fixed primitive b/?/i/u/f/c/S/a/U/V/O codes and selected widths; structured lists of two/three-element field tuples with optional subarray shape and nested field lists. Unicode payload width is four bytes per character. Unsupported datetime, offsets/titles/dictionaries and arbitrary aliases remain OPEN. For non-object dtype, exact itemsize-times-elementcount must equal remaining payload length. For object dtype, only the following pickle is statically reviewed; actual ndarray identity, header/pickle shape/type equivalence and object semantics remain OPEN.

Defaults: input 16 MiB; member 8 MiB; expanded ZIP total 32 MiB; 256 ZIP entries; 100,000 opcodes; 50,000 symbolic nodes; 10,000 stack entries; memo size/index <20,000; 100,000 graph edges; 1,000,000 key traversal work steps; operand 2 MiB; 64 streams; 512 findings; JSON report 256 KiB; NPY header 32 KiB, AST 2,048 nodes/depth 32 and dtype recursion 16. Paths <=1,024 UTF-8 bytes and 32 components, extra fields <=4 KiB. Limits can only be lowered, with report minimum 2 KiB. Budget exhaustion is INCOMPLETE/OPEN, preserving FAIL evidence. These are parser work/memory bounds, not a hard operating-system CPU/memory isolation guarantee.

File reading uses existing directory descriptors, O_NOFOLLOW/O_DIRECTORY/O_NONBLOCK, POSIX directory-relative capability checks, regular-file type, byte limit and before/after dev/ino/size/mtime/ctime plus actual read length. CLI and file input failures use constant OPEN diagnostics without paths or source content. Programmer misuse of the bytes/limits API raises constant ValueError. Whole-model safety, loader version/bindings, actual behavior, arbitrary embedded serialized bytes, firmware/framework dependencies, applicant qualification and provider approval remain OPEN. This is the bounded new selection mechanism, not the full upstream platform.
